# AGENTS.md - working in the TreadOps repository

Read this before editing. The implementation contract is the TreadOps blueprint (PDF); departures are ADRs in
`docs/adr/`.

## Layout
- `packages/treadops_ml` - data, transforms, train, evaluate, export/parity, package, monitoring, replay.
  The DVC pipeline depends on these files: editing (or auto-formatting) them invalidates `dvc.lock` stages.
- `packages/treadops_agent` - LangGraph copilot, guardrails, tools, LLMOps tracing, offline evals.
- `services/api/treadops_api` - FastAPI (/v1), SQLAlchemy models, services, CLI.
- `services/worker/treadops_worker` - Celery task runner, outbox dispatcher, job handlers.
- `apps/web` - Next.js App Router UI + BFF. Read `apps/web/AGENTS.md` (Next 16 has breaking changes).
- `configs/` - versioned, validated configs; the API only accepts allowlisted recipe IDs.

## Rules
1. Never invent data, counts or metrics. Every number shown must come from a stored run or API response.
2. Never train on calibration/policy/test roles or anything descended from them; replays are never eligible.
3. A bundle is promoted only through `POST /v1/deployments/promote` (gates passed, warm-up, expected
   generation). Never write the deployment pointer directly.
4. Status lives in SQL. Celery delivery is at-least-once; every handler must be idempotent.
5. Keep secrets in `.env` (generated by `make env`); never print or commit them.
6. Commit with the repo-local identity; end messages with the Co-Authored-By trailer used in history.

## Commands
`make help` lists everything. Typical loop: `make infra migrate seed-demo`, `make dev`, `make test`.
